# 发现与日报周报：本地按需维护

运行时目录为 `public/assets/catalog.json`。新闻、企业和报告继续使用既有 ID，报告保存文章引用。

## 页面操作

- 新企业、行业报道打开近21天首次收录的连续列表。最近一次更新新增的企业和报道置顶，显示红色NEW；较早内容接在下面。地区和下拉条件作用于整个连续列表。
- 行业报道排除固定九家媒体来源及其报道，入口计数和该页面重点情报使用同一范围。
- 再次点击已选入口恢复进入前的检索。企业和报道列表保留“全部来源”；日报和周报不显示历史选择框及返回来源按钮。
- 顶部搜索、研究方向和清空条件退出发现列表，检索完整资料库。日报周报阅读期间使用目录筛选，返回目录并应用条件。
- 企业和报道列表取消历史批次选择，旧批次链接也打开连续列表。浏览器前进后退及详情返回保留。
- 21天按北京时间首次收录日计算，包含当天共21个自然日，第22日自动从发现列表移除；已有内容的修订不重置期限。过期内容也移出重点情报入口，已生成的日报周报仍按保存记录读取。
- 网页按钮“从已收录资料生成”整理当前目录；联网查找由用户主动发起的更新流程执行。
- 企业发现的动作依据包含媒体新闻及公司公告、官网动态；行业报道列表只展示媒体新闻，并继续排除固定九家媒体来源。
- 列表、正文、详情、导出稿使用事件摘要。删除管理层关注重点、核查限制提示及防御性模板；不将这些内容搬入详情。

## 每次更新流程

1. 保存当前目录及工作区差异，确认用户指定的更新时间；默认北京时间当天。
2. 从目录读取全部活跃媒体来源，逐家检索，包括固定九家及后来加入的来源。查找 IDC/AIDC、算力租赁、项目建设、交付、服务器、液冷及电力报道；入口是地区栏目时仍检索该媒体全站。
3. 覆盖国内、东南亚及其他海外市场，不继承网页当前地区、关键词或发现批次。日报查当天，周报查上一完整周，同时补充开放搜索、企业公告及政策原文。
4. 保存每家媒体查询和选中文章读取结果。索引不足时查看媒体列表并沿正文链接读取，记录失败请求；同一原文、转载及同一事件合并处理。
5. 阅读正文、日期及署名后，编写50～100字左右的新闻摘要，自然表达计划、签约、发布、投运等阶段。已有原文沿用原ID，企业身份、历史核查记录及财务数据保留。
6. 新建 `data-candidates/` 下的资料批次输入，使用新 `batchId` 和实际北京时间。日报 `issueRequests.date` 填写更新日期。周报按《周报研究规则.md》另行整理八个板块及全部候选的采用理由，保存独立周报输入。旧资料批次仍按原口径重放。
7. 执行 `node scripts/discovery-update.mjs 已核批次.json`，再执行数据校验、测试、构建及浏览器验证。批次重放幂等，原始输入不覆盖。
8. 执行 `node scripts/weekly-update.mjs data-candidates/本期周报.json` 生成战略周报新版，再执行校验。执行 `node scripts/export-briefs.mjs 输出目录 YYYY-MM-DD`，导出与页面一致的最新日报、周报。交付本地结果，保持原有发布授权边界。

## 日期与选择

- 日报按原文所属日选择，最多8条，通常5～8条；其他文章保留在行业报道和来源目录。跨时区文章采用可确认的北京时间日期。
- 周报默认上一完整周周一至周日，使用北京时间。2026-10-14或10-18更新取10-05至10-11；10-19更新取10-12至10-18。固定八个研究板块，核心摘要3～5项、深度分析1～3项、下周跟踪3～5项；全文不限制为五篇新闻。完整规则见《周报研究规则.md》。
- 新版周报保存 `weekPolicy`、`requestedDate` 和明确的 `periodStart/periodEnd`。旧记录按原保存日期和直接链接读取；旧半周稿不进入默认周报。
- 同周周报再次生成保存新版，以生成时间区分，优先显示最近一版；原版本保留正文及来源快照。同一周报输入重放保持不变。日报沿用同日同批次重放规则。
- 全文尚未读取的书目条目保留原文入口，不参与新闻摘要或报告生成。文章核查元数据留在维护数据中。
- 固定九家媒体身份、7/15/30天预览窗口及核心企业、财务、事项关系保持兼容。
