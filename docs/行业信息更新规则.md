## 3. 同行公司重大动作时间线

### 3.1 每轮必须检查的事项

对固定追踪公司的新闻和公告，逐篇检查是否属于重大动作：算力服务／租赁合同、重大客户合作、数据中心建设扩建及投运、重大设备投入、融资、投资并购、技术升级，以及直接影响经营的监管事项。

重大动作优先查上市公司披露公告、巨潮资讯网、证券交易所等官方原文；公司官网和投资者关系活动记录补充经营进展，媒体线索须回查原始披露。

**对经营、资源投入或战略有显著影响的已核事项，必须同步建立或更新公司重大动作记录，不能只停留在行业报道、日报或“相关媒体报道”中。**金额规模、合同期限、客户及资源承诺、交付要求和公司经营体量共同决定重要性，不以签约新闻数量凑时间线。

### 3.2 同一事项连续跟踪

- 一个独立合同或项目对应一个稳定事项；后续采购、融资、交付、验收、计费、回款、变更或终止，追加到同一事项，保留前序节点。
- 每轮更新先复查已有重点事项，再补充新事项。对尚在履约的重大合同，持续查公司公告、定期报告、投资者交流及可靠媒体的新增证据。
- 只有新事实才新增节点；重复报道只补来源，未取得新事实时不改业务阶段，不把维护日期当作进展日期。
- 事件日期与公告日期分开。仅能确认披露日时，节点标题使用“披露……”；不将“近日签署”自行填成某个签约日。
- “计划、拟建、签约、生效、在建、投运、验收、尚未交割、延期、终止”等真实阶段准确保留。合同金额、计费收入、利润和现金回款分别记录。
- 新闻、公司事项及报告通过同一公司和事项关联，避免一个事项重复建档或归到相似名称公司。

### 3.3 算力服务合同的跟踪重点

| 跟踪环节 | 后续需要核对的信息 |
| --- | --- |
| 合同与订单 | 服务内容、金额及含税口径、订单期限、生效条件、调价、续期和解除条款 |
| 资金与设备 | 自有资金、融资签约及提款、实际设备采购、付款及到货规模 |
| 机房与配套 | 部署地点、可交付电力、冷却及网络、建设和上线安排 |
| 交付与验收 | 分批交付量、验货、性能和稳定性测试、客户验收日期及确认量 |
| 计费与收入 | 服务起算日、按月／按量结算、实际计费规模、财报确认的相关收入 |
| 回款与变化 | 回款及应收、延期、减量、合同调整、解除或终止，以及对投入和经营的影响 |

不同环节只有取得相应资料才记录实际完成；不以签约总额推算已实现收入、利用率、机柜数或GPU数量。

### 3.4 协创数据专项跟踪实例

- 事项：协创智算与客户签署《算力云服务协议》，预计总金额不超过**374.90亿元（含税）**。
- 原始依据：协创数据2026-153号公告，披露日2026-10-19；[公告原文](https://static.cninfo.com.cn/finalpage/2026-10-19/1225610425.PDF)。
- 已确认阶段：协议已生效；订单一般自最终验收合格且客户出具报告次日起服务60个月，按月结算；采购订单另有起算约定的，按订单执行。
- 跟踪顺序：资金和设备投入 → 机房及配套 → 分批交付／验货 → 客户验收 → 计费和财报收入 → 现金回款；同时核对合同变更与落地偏差。
- 以后每轮行业更新都检查这一事项的新增资料，在同一事项追加进展，不重复创建一条“374.9亿元签约”。

### 3.5 时间线展示

保持横向时间线，按真实日期排列，默认展示最重要的6—8项，不补无关事件。保留事件类型筛选、悬停信息、原文跳转和“查看全部”。不恢复“重大动作标题及简要概述”重复区域。

## 4. 公司相关媒体报道

- 优先查找证券时报、上海证券报、中国证券报、证券日报、财联社、第一财经、21世纪经济报道等权威财经媒体，再补充可靠行业媒体。包括公司自身没有发稿的报道；原发布者、署名、发布日期和原文链接保留。
- 时间范围为近三个自然月，并与当前所选时间范围取交集。切换公司或时间后，列表与范围说明同步变化。
- 使用紧凑列表，保留“查看全部”和可拖动调整窗口高度。
- 新报道涉及重大经营动作时，按第3节核查原始依据并同步公司事项；媒体解读与公司公告分别保留来源身份。

## 5. 公司财务

- 每次行业更新，同步检查现有公司的最新正式财报，更新营业收入、净利润及同比。
- 标明年份、报告类型、起止期间、单季度或累计、金额单位及利润归属，附财报原文。业绩预告不替换正式已实现数据。
- 紧凑卡片显示最新已披露数据与报告期；同比增长用红色↑，下降用绿色↓，后接百分比。
- 亏损扩大、亏损收窄、由盈转亏、扭亏为盈直接用文字说明，并显示本期及上年同期金额；百分比辅助理解。
- 对照同一主体、期间、单位及口径计算；公司合并收入、设备销售、IDC运营及算力租赁收入分清。原件未取得时保留原已核数值。

## 6. SMM算力价格看板

- 当前采用人工更新。每轮行业更新同步核对免费公开页面的四组价格、区间、报价日期与涨跌幅，不接入需付费或授权的自动采集。
- 保留卡型、显存、地区、整机／单卡、租期、价格类型、单位及原站链接。
- 每条显示报价日期和最近核对时间；涨跌幅写清比较日期及依据。依据不足时显示“暂无可比数据”，旧报价按已确认规则显示历史快照及日期。
- 同口径历史报价可用于计算比较涨幅；报价不能改写为成交价，也不因核对日期变新而刷新原报价日期。
- 保持现有悬停展开布局与延迟，不将完整看板常驻占用目录空间。

## 7. 每日快报

- 先搜索，再汇总；北京时间当天截至本轮更新时间，覆盖建设、租赁价格、企业、设备、电力和政策。
- 同一事件合并，按重要性精选约5—8条，不为凑数收录无关消息；其他合格文章保留在资料库及适用板块。
- 重要内容按“发生了什么 → 为什么重要 → 业务影响”展开，保留发布日期、来源和原文。
- 页面生成按钮仅整理已入库资料；用户发起行业更新才执行完整联网检索和入库。
- 日报中的同行重大动作，发布前逐项核对是否已经同步第3节。

## 8. 行业周报

- 采用战略发展部研究视角。默认周期为**上一完整周北京时间周一至周日**；首页、生成器、阅读页及导出使用同一日期。
- 例如2026-10-20更新对应2026-10-12—10-18；周日更新仍取上一完整周，周一才切换到刚结束的一周。
- 八个固定板块：①本周核心摘要（3—5项）；②政策与行业环境；③同行企业与重大项目动态；④算力租赁市场与经营数据；⑤技术进展与上下游产业链；⑥本周重点事件深度分析（1—3项）；⑦战略判断与业务启示；⑧下周重点跟踪事项（3—5项）。
- 固定检查监管新规、交易所最新处罚案例、香港SFC收购条款，以及新加坡MAS／SIC收购规则与个案。原发布时间、生效日、征求意见与现行条款背景分开。
- 国内和东南亚为重点，同时覆盖全球重要变化；不能仅因某地区文章易获取就集中于该地区。
- 关键数字写清统计时间、单位和口径；事实、来源观点及独立研究判断分开。无可靠新增的板块简述，不编造数字或填充新闻。
- 同周更新保存新版本并保留内部记录，网页不建设周报历史记录或历史期次入口；不恢复“管理层关注重点”整段。
- 详细研究与资料结构见[周报研究规则](周报研究规则.md)。

## 9. 搜索、切换与近期发现

- 区分“信息来源”和“具体资料”，切换相关入口保留适用关键词、地区及时间；条件必须变化时给出提示。
- 在行业报道内继续搜索时保留报道范围，不静默回到来源目录；文章始终支持按原文发布时间从新到旧排序。返回及浏览器前进／后退恢复对应条件。
- 新企业和行业报道采用连续列表，不按历史批次分类；最近一次更新新增内容显示红色NEW并置顶，较早内容接在下面。
- 近期发现保留21天，从首次收录日算，含当天；修订不重置首次收录日。该规则是展示保留期，不是把联网搜索限制为近21天。
- 超期内容移出近期发现；公司重大事项、财报依据与已生成报告按各自规则保留。公司媒体的三个月窗口独立执行。

## 10. 阅读、文案与导出

- 删除列表、正文、详情及导出稿中的冗余防御性字段、免责声明、重复口径说明和无价值解释，不转移到其他区域。
- 保留影响业务判断的实际阶段、日期、单位、必要统计口径与事实来源。
- 日报周报顶部保留简明摘要、可点击章节目录；当前位置在目录中高亮。阅读时收起占空间的筛选与推荐，保留返回检索入口。
- 支持复制摘要并带报告日期、来源，支持打印／保存PDF；导出与网页使用同一份内容。
- 不随资料更新改动导航、布局或加入无关装饰和重复内容区域。

## 11. 验收与默认部署

**用户于2026-10-20明确授权：以后只说“更新信息”，且没有其他明确限制时，完成更新、检查通过后直接部署，并返回正式网址。**本次协创合同补录、规则整理及此前本地行业更新一并按此授权发布。

- 用户明确说“先本地”“不要部署”“仅出方案”或“等待审核”时，按当次限制执行；普通更新不再重复请求部署确认。
- 仍使用现有GitHub main → Cloudflare Pages发布链路。发布资料、必要修复、测试与规则文件，不夹带无关本地内容，不改安全权限或付费设置。
- 发布前完成数据校验、回归测试、构建，实际检查桌面／手机主要页面、公司及时间切换、事件筛选、来源跳转和内容关联。
- 对新收录的重大合同，必须实际在对应公司的时间线上看到正确节点；只在日报或资料库找到不算完成。
- 通过部署状态、对应提交和正式站页面确认上线后，附[正式网址](https://idc-aidc-navigator.pages.dev/)及适用页面链接。没有数据变化时不制造空部署。
- 无后台定时采集；“持续跟踪”落实为每次用户发起更新时复查同一事项。

## 12. 用户反馈与规则维护

- 用户确认的新规则当轮写入本文件对应板块，并同步修正操作文件中的冲突表述；不能只留在聊天中。
- 后续窗口先读本文件，再读[按需更新指令](按需更新指令.md)、[资料维护说明](资料维护说明.md)及本次涉及的专项规则，随后检查当前资料及工作区差异。
- 工程维护使用唯一资料入口`public/assets/catalog.json`，沿用稳定公司、资料和事项ID；构建生成`dist`，不手改一份平行数据。
- 规则变动保留日期，交付时给用户规则文件链接。示例中的日期和金额用于对应事项，不作为其他公司的默认值。
