# 资料维护说明

本项目是按需维护的静态研究导航，国内优先，持续关注东南亚六国。先读用户已确认的[行业信息更新规则](行业信息更新规则.md)，按板块执行；操作提示见[按需更新指令](按需更新指令.md)。唯一资料编辑入口是 `public/assets/catalog.json`；核查历史追加到 [来源核查记录](来源核查记录.md)。不设置定时采集、维护排班或后台任务。

当前结构为 `schemaVersion: 2`。正式入口为 `src/main.jsx`，界面由 `src/App.jsx`、`src/components.jsx`、`src/styles.css` 实现；`src/catalog.js` 在构建时导入 JSON。历史 Vue/Homer 组件不负责正式检索界面。

## 1. 编辑顺序与稳定身份

1. 读取最新仓库说明、目录和核查记录，确认本次范围及真实完成的检查范围。maintainedAt 不代表所有来源都检查到了该日。
2. 打开持续入口及具体原文，记录实际取得范围、日期、地区、访问条件、主体与限制。搜索摘要不能替代原文；失败不推定为付费或永久下线。
3. 按稳定 ID 定位已有来源/资料，先判断重复，再新增或修订。保留旧链接、真实发布日期与历史成功核查日。
4. 逐篇填写资料自身字段及必要主体关联。来源无可确认资料时保留准确空状态，不为填满预览造内容。
5. 逐篇检查固定公司重大合同等经营动作是否已关联公司事项；已核重大动作及后续履约进展同步时间线，不能只录报道。追加核查记录，完成校验、测试、构建和HTTP预览。按2026-10-20用户授权，无其他明确限制的“更新信息”默认检查通过后部署；当次仅本地或待审核的限制优先。

JSON 使用 UTF-8，不允许注释或末尾逗号。未知日期用 null，不是字符串 "null"、空字符串或维护日期。稳定 ID 使用小写英文、数字与连字符；来源改展示名不改 ID，不按分类复制来源，也不重新导入整库。

根字段为 schemaVersion、title、maintainedAt、categories、companies、sources、reports。代码与构建产物不保存第二份需要人工同步的行业资料。

## 2. 五个分类的边界

唯一业务字典为 catalog.json.categories，每类包含 id/name/question/icon，数组顺序决定展示顺序。正式界面不再从名称、介绍或关键词数量推导分类。

| ID | 名称 | 主旨与边界 |
|---|---|---|
| industry | 行业供需与动态 | 项目建设、扩建、交付、投运、市场供需、供电与资源条件、行业统计与研究、技术落地；泛 AI 和无关行情不收。 |
| rental-prices | 算力租赁与价格 | GPU/算力租赁报价、指数、卡型供需、合同交付条件和方法；机房容量租金、服务器销售或一般云收入不能冒充 GPU 租赁。 |
| policy-planning | 政策与规划 | 发展目标、产业布局、支持鼓励、财政税收及相关官方解读；政府统计和项目新闻不因发布者身份自动归政策。 |
| regulation | 监管与合规 | 准入、许可、强制义务、监管草案、程序解释、执法、关注公司的问询及直接相关上市/交易/披露规则；普通公告和 IPO 申报不自动成为监管个案。 |
| listed-companies | 同业上市公司动态 | 关注公司的业绩、运营披露、公司级并购融资、重大合同、资产交易与经营风险；单项目开工/投运主归行业，问询处分主归监管。 |

来源 categoryIds 可覆盖多类；每篇资料只有一个 primaryCategoryId。一份材料兼有多个视角时，用 companyIds、少量主题标签和相关链接表达，不复制多条。政策看“如何发展和支持”，监管看“适用何种义务、如何审批执行和追责”。综合文件按主要问题归类。

行业辅助标签限于项目建设与扩建、供给与需求、供电与资源条件、行业统计与研究、技术落地等必要标签，用于展示和检索，不另建多级分类。

## 3. 来源与资料分别录入

### 来源 Source

保留 id/name/organization/sourceType/categoryIds/purpose/questions/metrics/aliases/tags/regions/frequency/frequencyNote/access/accessNote/entryUrl/entryType/methodologyUrl/caveats/featured/verifiedAt/verificationStatus/verificationNote/lastCheckAttemptAt，新增必填 visibility。关联公司时填写 companyIds。

entryUrl 指持续栏目；只核实机构首页时用 entryType: "机构首页"，不编造深链。methodologyUrl 无已核入口时用 null。来源地区与访问条件仅说明栏目覆盖和总体门槛，不替代单篇文章信息。frequencyNote/accessNote/caveats 写清更新节奏、获取限制和分母口径；来源频率不能变成每篇资料的更新频率。

featured 只表示常用入口，不是核查等级或归档开关。trackingNote/subscriptionNote/subscriptionUrl 是已有可选说明，保留有效历史内容；本轮不新增订阅、注册或通知任务。

### 资料 Report

| 字段 | 规则 |
|---|---|
| id/sourceId/title/url/summary | 稳定资料 ID、已有来源 ID、原标题或准确译名、实际阅读入口、自写中文摘要；不得有孤立来源。 |
| primaryCategoryId | 必须为五类之一的单一 ID，不继承来源多分类。 |
| regions | 本篇实际涉及地区；未知为 []，并填写 regionNote。不能按媒体总部、上市市场或来源覆盖补国家。 |
| kind/judgmentTypes | 内容形式与事实/观点/预测分别填写，不按来源类型猜测。 |
| publishedAt/dataPeriod | 发布日期与统计期独立；缺证据时为 null。官网上架日期与最初披露日期不确定时须在说明限定。 |
| originalPublisher/originalUrl/url | 原发布机构、可核实原文、实际阅读入口分开；未取得原文地址可用 originalUrl: null。转载不可冒充原发。 |
| access/contentScope | 本篇获取条件与实际取得范围独立，不照抄来源总体门槛。 |
| companyIds | 必填数组；不涉及主体时为 []，有引用时必须命中主体字典。 |
| visibility/visibilityReason | 展示状态；补充参考或归档须说明原因。 |
| verificationStatus/verifiedAt/verificationNote/lastCheckAttemptAt | 当前核查状态、历史成功日期、实际范围与本次尝试分开；每次变动写清说明。 |
| stage/eventType | 涉项目、交易或监管事件时填写；普通新闻不强制虚构阶段，未知写待核或 null。 |
| documentStatus/effectiveAt/deadlineAt/jurisdiction | 政策/监管按需记录草案、发布、生效、解释、个案状态及法域；生效/截止日可合法位于未来。 |
| eventId/relatedLinks/duplicateOf | 有共同事件、补证或真正重复时使用，不强制所有资料建事件。 |

contentScope: full 只说明所指文献全文已读：完整阅读新闻稿不等于阅读整份中报，完整阅读印发通知不等于读取规则附件。完整报告只取得介绍页时用 abstract；长报告只核相关章节用 partial。摘要须保留“拟、预计、草案、未取得、尚未交割”等限定，不将预测变成已实现事实。

“已核查”只说明核对过所列材料和范围，不等于独立证实材料中的全部说法。券商观点保留机构归属，媒体采访保留报道性质，市场测算保留统计口径。只保存必要书目信息、公开链接及允许范围内的自写说明，不存受限全文；原站限制摘编时按其限制处理并写入核查说明。

## 5. 展示状态、SMM 与去重

- active 进入正常列表和活跃计数；reference 默认隐藏，开启“显示补充参考”后可见；archived 不随该选项恢复。已确认重复项不进入正常计数、预览或列表。
- 只有标题/目录、搜索摘要或未取得内容的资料不能设为 active。来源入口可以保留待核，但不能因此虚构具体资料。
- 来源与资料可见性独立。一般来源降级不自动隐藏仍有效的历史资料；SMM 按下列专项决定处理。
- 保留 smm-rental 独立行情来源，失败仅写真实状态，不伪造最新报价。smm-weekly 与 smm-weekly-public-commentary-104134387 归档，保留原 ID、原 URL、历史核查与移除原因，不改挂行情、不更名回流、不建替身来源。旧详情链接显示归档说明。

去重先核稳定 ID、原文 URL、发行人/文号、机构与报告日期、事件及实际进展。相同材料补证更新原记录或 relatedLinks；真正新阶段可新增，旧文补证不改发布日期。relatedLinks 至少写 url/publisher/role，确认后才写日期，同组不重复 URL。duplicateOf 必须指向已有同类对象，不能自指或成环。

同 URL 的不同时点数据快照、方法与行情共址可合理保留，必须说明时点和用途，不能设 URL 全局唯一硬限制。重复执行同批资料不得新增重复来源、资料、事件或相关链接。

## 6. 国内、东南亚、筛选与首页预览

裸首页默认 scope=domestic，包含本篇已明确标注的“中国”“中国香港”；sea 为新加坡、马来西亚、泰国、印尼、越南、菲律宾；all 不限地区。“全球/亚太”标签不证明特定国家覆盖。机构所在地、证券市场和项目所在地分开，港交所规则的中国香港法域不变成所有内地项目适用规则。

同维度多选为 OR，不同维度为 AND。资料筛选读取本篇的主分类、地区、类型、获取条件；仅来源发布频率取自来源。来源目录可因自身字段命中，或因**同一篇资料完整命中所有条件**而出现，不能拼接不同文章的国家、分类和关键词。选择资料类型时必须有该类型的匹配资料。混合权限来源下的免费公开稿件仍能在免费筛选找到。

东南亚动态按文章国家判断，不要求来源先带专题标签；国内公司或媒体的已核六国资料也可进入。专题来源保留有效专题入口并接纳实际匹配资料的来源，按 ID 去重。资料地区未知时只在不限地区中参与检索。政策/监管在全部地区视图按国内、东南亚、其他/跨地区分组，一篇仅出现一次。

每个来源的“最近已收录”直接从可展示且符合当前条件的资料取一条，按真实发布日期降序，未知日期后置、同日稳定；不使用核查日或维护日置顶，也不另存 latestTitle/latestSummary。没有任何资料与当前无匹配资料使用不同空状态，均不表示原站无更新。只有方法页时明确标“参考资料/方法说明”。来源名开详情，访问原站开持续入口，近期资料标题开该篇原文。

### URL 兼容

检索链接保留 q/topics/regions/types/access/frequency/sort/view/source，增加 scope 和 showReference=1。旧主题先映射再清除无效值：infrastructure/market→industry，rental→rental-prices，financial→listed-companies，policy→policy-planning + regulation，合并去重。

无有效参数才默认国内；没有 scope 的有效旧检索链接保留不限地区。显式细分地区优先规范范围；东南亚两个旧 view 始终限定六国，异常地区参数不能导入纯国内内容。清空条件保留当前 scope，回裸首页才恢复国内。复制链接、刷新、前进后退均应恢复相同条件；归档来源的旧 source=... 链接保留明确说明。

## 7. 日期与核查记录

publishedAt 为所指材料真实发布日期，dataPeriod 为统计期/时点，verifiedAt 为最近真实成功核查日，lastCheckAttemptAt 为最新尝试日，maintainedAt 为目录维护批次。采用北京时间 Asia/Shanghai 日历日；外部时区必要时在说明中保留。不能从 URL、报告年份或工具抓取时间猜发布日期。

发布、成功核查、尝试及维护日期不得晚于实际执行日。effectiveAt/deadlineAt 可在未来，但未来生效文件不得写已生效；咨询/草案与现行法规分开。未知日期显示待核并后置。界面改造、结构迁移、运行测试和打开详情都不产生新的外部成功核查日期。

verified 须实际读到对应文献或明确范围；partial 说明已读何种部分；unverified 的成功日为 null；unreachable 写明超时、403、空正文、解析失败或验证墙等实际观察。曾经成功、本次失败时保留旧成功日与有效资料，补本次失败，不能说今天重读成功。来源栏目可读与资料全文可读分别判断。

核查记录只追加新批次，写明原 URL、文章日期、取得范围、状态、真实修改及未覆盖部分；历史错误的修订在新批次明确说明，保留旧观察。单个来源失败后继续其余工作，不绕过登录、付费、验证码，不购买或自动注册。

## 8. 校验、构建、本地预览与发布边界

在仓库根目录运行：

```powershell
pnpm validate
pnpm test
pnpm build
pnpm preview --host 127.0.0.1 --strictPort
```

以终端实际 HTTP 地址预览，不能双击 dist/index.html。校验检查结构、枚举、真实日期、来源/公司/分类引用、重复关系及 HTTPS URL 格式，不检查远端可达性或保证事实正确。测试检查规则，构建生成静态产物；只记录实际执行结果，不预填通过。

重点检查新增和修订条目、近期预览、国内默认、六国过滤、免费稿件、公司检索、日期未知、补充参考与归档、原文/来源/详情三个入口、复制链接和刷新恢复。资料增加、修订、无新增、仅补核、失败、重复与未来截止日等更新行为使用隔离测试，测试样例不得进入正式 JSON。

**修改 JSON 后必须重新构建。** 当前 React 界面通过 src/catalog.js 静态导入资料，dist/assets/catalog.json 另为复制产物；只替换该 JSON 不会更新已打包界面。正常只改源 JSON，不手工编辑 dist；检查源/构建 JSON 一致及页面实际渲染内容。

本地验收与发布分开。取得本次发布授权后才按现有 GitHub → Cloudflare Pages 链路推送获准分支；不擅改部署方式、强推或覆盖他人提交。发布后核对提交/部署状态及正式页面实际渲染，不能只检查公开 JSON 就称上线成功。当前优化默认只执行本地阶段；仓库中的提示词模板本身不构成发布授权。


## 二期本地候选补充 · 2026-10-08

### 子方向与公司

subcategories 固定父类与 order；资料 primarySubcategoryId 为单值或 null，不从来源关键词继承。来源 subcategoryIds 只表达已确认栏目覆盖；没有文章时显示入口及空预览，不能满足资料类型筛选。现有主类、ID、日期不得因迁移重建。

单父类显示子方向单选，多父类清除并提示；数字考虑其他条件，来源/资料各按自身ID去重。公司 core 六家按光环新网、行云科技、世纪互联、协创数据、万国数据、东阳光排列，三运营商单列；七家参考折叠。公司全景按显式 companyIds 跨主类汇总，普通资料视图仍严格主类。

### 事件及证据

2026-10-20补充：对固定追踪公司有显著经营、资源投入或战略影响的已核重大合同、项目、融资并购等，更新资料时必须建立或维护对应事件。签约之后沿同一event.id跟踪资金设备、机房配套、交付验收、起租计费、财报收入、回款及合同变更，不为后续报道重复创建独立事件。披露日期已知但实际签约日未单列时，使用“披露……”节点及其真实披露日。验收时须在公司时间线上实际看到新增节点，新闻与重大动作联动才算完成。

events 的 id 稳定，companyIds/participants 明确关联主体及角色，regions 记录事项真实涉及地区；不得按总部补国家。type 仅为 acquisition/capital/contract/risk。一个事项跨公司共用一个对象。relatedEventIds 为相关但独立交易，允许双向关联但不能自指；不是合并业务阶段。

每个 milestone 必须有主证据 primaryEvidenceReportId，并包含于 evidenceRefs（reportId、locator、role）。publishedAt 只从主报告派生；occurredAt 未单列填 null。isProgress 区分进展与线索；verificationLevel 区分官方正文、指定披露报刊、媒体、目录及待核，不是审批阶段。不要根据阶段大小自动推进：撤回、延期、终止也可成为真实新节点。

currentSummary 为唯一人工核准结论，basisMilestoneIds 与 latestVerifiedMilestoneId 只能引用本事件已核进展。新近补录旧公告、摘要修订、访问失败不自动替换当前结论。媒体、未知日期、仅线索不能成为最新已核节点。摘要与证据冲突时保留当前可靠依据，追加 conflict 尝试和限制，不猜测结论。

### 六类时间

1. occurredAt：事项实际发生日，未明确为 null。
2. report.publishedAt：原文公开披露日；不得从 URL 或核查日猜测。官网显示日与文件落款有差异时写入 dateNote，不混作实际签约日。
3. report.verifiedAt：成功取得本篇材料的日期与 scope。
4. lastCheckAttemptAt / review.lastAttemptAt：最近实际尝试日，失败不能覆盖历史成功日。
5. review.checks[].checkedFrom/checkedThrough：该渠道实际完成的有限区间，未完成均为 null；no-new 必须有真实已查区间。
6. catalog.maintainedAt：本站维护批次，与业务进展无关。

review 记录每次渠道、URL、尝试结果、说明和覆盖区间；公司 disclosureReview 使用同一结构，六家逐家显示。只读了列表首页或正文一部分应为 partial。blocked/conflict 不能覆盖既有成功历史和当前结论。

### 本地合并与重复运行

scripts/reviewed-batch.mjs 导出 mergeBatch(original,batch)，返回校验通过的新对象，不写文件、不联网。batch.reports 为完整新增记录或已有 ID 的明确修订；普通修订保护 sourceId、原 URL、发布日和原发布者，历史核查说明只能追加。批次 events 使用 {event:{id},nodes,review,current}；新增事件须提供完整 event。current 须明确 reason=progress/correction/withdrawal，以及人工选择的摘要/依据/最新节点/限制。无 current 时永不自动推进。失败、冲突或有限无新增检查不能附带 current 覆盖。

同批重复运行保持字节级 JSON 结果相同；节点 ID、报告 ID、证据引用及 relatedLinks 不重复。同一主报告不能另建相同业务节点；无增量转载采用旧 report ID 或 duplicateOf，不做新进展。确有不同版本但 URL 相同，双方必须维护不同 documentVersion 并保存版本核验说明；不能因同 URL 一律删除真实后续文件。SMM 归档报告、归档来源及同 URL 归档内容不可复活。

结构校验不代替外部事实核查。数据写入前调用 validateCatalog，再构建和核对 HTTP 页面；测试夹具只进入隔离目录，不进入正式 JSON。
# 第三轮补充（2026-10-09，本地候选）

- `changeBatches` 是可选追加台账，不替代唯一资料主文件。每批记录稳定ID、北京时间、实际范围、输入SHA-256、前批ID、实际变化与检查。`new-record`、`historical`、`event-node`、`revision`、`evidence`可同时出现；检查不归新闻数。重放同输入不改变条数和时间，冲突拒绝，合并全体校验通过后才写回。
- 原文日期未知继续为null，可用dateNote保留可靠月度署期；不能由PDF路径、观察日、核查日推导日级首发。7/30天分别含截至日向前6/29日，URL含asOf；未来日期排除。公司当前事项独立于资料日期筛选。
- 显式`relatedSubcategoryIds`只能指向同一主类其他子方向，需`relatedSubcategoryNote`。严格结果≤2时最多展示3条关联；不扩大国家、访问权限和时间，不混入严格计数。一个资料仍仅一个主子方向。

- 阅读层级：普通资料默认标题、原日期/机构、摘要和原文入口；常规完整字段收在“查看依据与口径”，筛选逻辑在“筛选规则”。拟议、未交割、草案、预测、仅摘要/原件待核仍直接可见。书目受限摘要不可因优化而扩写转载。
- SMM观察快照与基准价不是实际成交价。2026-10-09观察行只显示10-08，无年份；publishedAt保持null。方法未核，不跨卡推算。归档周报继续不参与正式结果。

## 第四轮增量规则（2026-10-12，本地候选）

仅本地实施与验收；本章及历史模板均不授予提交或发布权限。本轮内容核查见《第四轮内容核查.md》，发现词见《第四轮发现词表.md》。唯一业务主文件仍为 `public/assets/catalog.json`；`docs/batches/phase4-content-20261012.json` 是审核输入，不是另一套业务数据。

### 产品归档与地区

`excludedProducts` 明确记录SMM订阅周报与国家能源局宏观用电统计产品。既有源/资料保持ID、原链接和原日期，visibility=archived，原因为用户决定。普通与参考结果、预览、推荐和活跃计数排除；旧source详情保留历史。批次和目录校验同时拦截换ID、换来源及改名回流。判定结合身份、原URL、产品名/标题，不对整个能源局域名或普通“用电”词封锁，也不从摘要中的否定句误判。具体接电/绿电政策仍允许按证据新增。

`scope=overseas` 只匹配明确境外地区，保留国内中国/中国香港、sea、all语义；全球、亚太或未知不凭“非中国”进入海外。东南亚专题始终限定sea。company.researchScope可为domestic/overseas/cross/pending，必须有identityNote说明；仅用于参考公司分组，不推导文章地区，不改变六家核心及三运营商。

### 财务与重要动作

对应资料可有一个 `financial` 对象，其他视图引用它。status=verified/pending；statementBasis固定actual-results，period记录明确报告期、类型、起止和可比上期；revenue/profit保留原指标名、原值、上期值、币种、单位、归属、change；evidence含已关联原URL及页码/表名；limitations写实际读取范围。普通新闻无需该字段。已核财务必须来自公司正式披露及实际取得内容，不能用预测替代；一份报告可同时含未来展望，但财务数字本身必须是实际业绩。

显示原币种，按万元/亿元两位小数转换，不改原值、不换汇。同比basis=reported/calculated/amount；计算同比保留公式说明并检查可比期，容许原披露四舍五入差异。零基数或负数盈亏只显示金额及亏损扩大/收窄、扭亏/转亏，不输出误导百分比。归属利润严格保留外国发行人原行，不能用普通股利润、合并净利润或调整指标顶替。

公司业绩按period.end再按原发布日期选择，与新闻7/30天、类型和关键词筛选分开；页面称“最近已核业绩”。若存在更新报告期待核，提示“上一期已核业绩”，不把旧一期无条件叫最新。普通来源预览仍只在匹配资料上显示。importantAction为已读重要公告的简短事实及阶段，和财务区域分开，不机械选择例行通知。经营变化和必要限制直接可见，原始值与常规说明折叠。

### 批次、官方补证及失败保护

使用 `applyBatchFile(file,batch)`：先mergeBatch及全量校验，再在同目录写临时文件并原子更名；相同输入无变化时不写回。不要直接覆盖Catalog。新增财务、archive、source等变化有独立批次类型；失败不产生成功台账，旧有效financial不允许以null清空。未知字段/日期/引用/D01冲突均拒绝。

本轮允许以 `nodeReviews` 对既有节点做reason=official-supplement的有依据核验升级，前提为主资料不变且具有关联官方同件；仍由current显式人工修订结论。不能借此改主证据或新增重复节点。资料原URL不改；按钮可优先使用role以“指定披露同件”开头的官方补证链接，历史第三方引用仍指向旧镜像。东阳光反垄断与证券审核/注册、交割、募资继续区分。

媒体authorship明确journalist/brief/platform-author/reprint/unknown，不能将平台名称当记者。先核公开正文，再写短摘要；受限全文及bibliographic-link-only约束不解除。原文发布日期、报告期、核查日、收录日和批次日各自保留。


## 媒体近期窗口补充（2026-10-12）

用户最终折叠规则：先匹配地区、研究方向、关键词等，再计算合格新闻数量；近7天不足5篇扩大15天，仍不足扩大30天，达到5篇即停止。30天不足按实际数量显示，0篇才暂无。封面加折叠最多5篇，最新一篇封面不重复；同日按稳定ID。各条显示原日期、地区、核心短摘要及核查限制；仅1篇无展开。具体边界、有限核查和本批19篇见《媒体近期更新规则.md》。公司财报、官方来源及手动历史查询保持原规则。

按需更新时由Codex检查原文并完成产业相关性、公司关联、实质增量、广告与转载去重判断，使用者无需逐篇人工筛选。正文或公开摘要不足的待核线索不用于凑5篇；保留书目受限提示，区分媒体观点、计划和已完成事实。结构校验仅保证字段与引用，不代替这项内容判断。沿真正完成的来源检查位置增量补查，并核对日期边界与重复转载；有限覆盖保留partial，不能把尝试日当完成截止日。

通过既有applyBatchFile追加资料并保留审核输入；新条目使最旧及超30天文章移出首页列表，但不删历史、不重建目录、不改原文日期、不因媒体自动生成事项节点。`getSourcePreviewSelection()`返回`{report,reports,days}`，非媒体仍最多一篇，旧`getSourcePreview()`接口保留。独立原生折叠默认收起，筛选文章集合变化时重置；不新增后台服务、定时采集或人工审核界面。

## 同业公司地区筛选补充（2026-10-12）
