# 资料维护说明

本项目是人工维护的静态研究导航。资料的唯一编辑入口是项目内 `public/assets/catalog.json`；页面组件和构建产物不保存第二份需要手工同步的行业资料。本说明中的 JSON 是初次交付的教学快照，后续以该资料文件为准。

本次项目实际位置为 `E:\Codex\2026-10-04\new-chat\outputs\idc-aidc-navigator`。D 盘不在本次工作区允许写入范围，因此使用指定的 E 盘工作区；没有移动用户已有文件。

## 1. 文件结构与编辑顺序

资料文件的根对象包含六个字段：

| 字段 | 类型 | 用途 |
|---|---|---|
| `schemaVersion` | 数字，目前为 `1` | 数据结构版本；日常增补资料不修改 |
| `title` | 文本 | 页面标题 |
| `maintainedAt` | `YYYY-MM-DD` | 维护者最后更新这份目录的日期 |
| `categories` | 分类对象数组 | 分类顺序、名称、研究问题和图标 |
| `sources` | 来源对象数组 | 持续栏目或稳定机构入口 |
| `reports` | 资料对象数组 | 具体新闻动态、报告、数据发布或方法说明 |

推荐操作顺序：

1. 先打开原始栏目和具体文章，核对机构、用途、获取条件、发布日期及统计口径。
2. 在 `sources` 新增来源，或定位已有 `id` 修改。不要因为同一机构出现在两个分类而复制来源。
3. 有可用原文时，在 `reports` 新增报告，用 `sourceId` 关联来源。没有可确认的报告可以暂时不添加，页面会提示暂未收录。
4. 更新核查说明和日期，以及根对象的 `maintainedAt`。说明本次实际读到什么、什么未能核实。
5. 运行结构验证、测试和构建，通过 HTTP 预览交互与外链，然后交付新构建。

JSON 不允许注释或末尾多余逗号；使用 UTF-8 保存。未知值用 JSON 的 `null`，不要填写字符串 `"null"`、空日期或维护当天代替未知发布日期。

```json
{
  "id": "gds-quarterly",

```

`id` 使用小写英文、数字与连字符，保持稳定；改展示名不改 ID。若确实必须更名 ID，同步修改所有报告的 `sourceId`。地区名称、标签和别名应复用已有写法，避免“中国”和“中国大陆”无意拆成两个筛选项。

`entryUrl` 指向持续更新栏目；没有核实稳定栏目时允许机构首页，并以 `entryType: "机构首页"` 说明。`methodologyUrl` 可以为 `null`。当前校验要求链接采用完整 HTTPS 地址且不含用户名或密码，不把搜索结果页当原文入口。

`categoryIds` 至少一项。数组第一项决定“全部来源”视图中的主归类，选择其他分类时仍可找到跨分类来源；总数量按来源 ID 去重。`featured: true` 将来源加入常用入口。

搜索覆盖名称、机构、用途、研究问题、指标、别名、标签、口径限制和频率说明。别名只帮助查找：例如 GDS 的“上架率”别名不意味着其面积利用率等同机柜上架率；区别必须写在 `caveats`。报告标题不参与来源搜索。

## 3. 完整报告示例与关联

下面的报告属于上面的来源，因此 `sourceId` 必须恰好为 `gds-quarterly`。

```json
{
  "id": "gds-2026-q2",
  "sourceId": "gds-quarterly",
  "title": "GDS Holdings Limited Reports Second Quarter 2026 Results",
  "url": "https://investors.gds-services.com/system/files-encrypted/nasdaq_kms/assets/2026/08/13/7-36-49/GDS%202Q26%20Earnings%20Release_0813%201200.pdf",
  "kind": "report",
  "publishedAt": "2026-08-13",
  "dataPeriod": "2026 年第二季度；运营指标截至 2026-06-30",
  "summary": "公司季度财务及运营披露，包含投运、签约和使用面积及利用率定义。",
  "verifiedAt": "2026-10-04",
  "verificationStatus": "verified",
  "verificationNote": "从官方季度栏目进入 PDF；正文第 2 页载明发布日期、所属季度及利用率定义。"
}
```

一条来源可以对应多篇报告。新增季度报告时使用独立、稳定的报告 ID，保留有参考价值的历史记录；不要只修改旧报告标题而继续使用旧 URL。报告标题保留原文或准确译名；摘要用自己的话说明用途，避免复制大段正文或受限全文。

`kind` 决定资料类型。`report` 为报告，`data-release` 为统计数据或业绩等数据发布，`methodology` 为方法说明。方法与栏目可能共用同一页面；这种情况须在核查说明中交代。公开周评、报告介绍和完整付费报告也要分别说明，不能相互冒充。

在首批资料中，SMM 行情与周报属于不同产品，保留两个来源；国家数据局阶段性算力披露与年度数字中国报告也分别建档。

## 4. 添加或调整分类

每个分类都需要 `id`、`name`、`question`、`icon`。例如现有“运营与需求兑现”类别采用以下结构：

```json
{
  "id": "operating-demand",
  "name": "运营与需求兑现",
  "question": "上架、利用、签约和收入情况如何？",
  "icon": "fas fa-chart-line"
}
```

修改分类名称或研究问题时保留 ID，即可保持关联。新增分类时在 `categories` 追加一个独立 ID，再将此 ID 写入相关来源的 `categoryIds`；图标使用项目已打包的 Font Awesome 类名。分类顺序由数组顺序控制。

删除分类前先移除或替换所有来源对它的引用，每条来源仍须至少属于一个分类。六个首批分类是 MVP 的基准；删除或替换需在交付说明解释，验证命令会给出基准清单提醒。不要将分类名称、颜色或图标当作来源权威性的排名。

来源级分类、地区、频率、获取条件及关键词共同筛选，不同维度之间为 AND。当前页面每个维度单选；筛选依据 `Source`，不是关联报告的统计期。

## 5. 枚举和必备说明

| 字段 | 允许值 | 录入原则 |
|---|---|---|
| `sourceType` | `government`、`company`、`research`、`commercial`、`media` | 政府、公司披露、研究机构、商业数据机构、行业媒体；不表示评级 |
| `frequency` | `daily`、`weekly`、`monthly`、`quarterly`、`semiannual`、`annual`、`irregular`、`unknown` | 日、周、月、季、半年、年、不定期、待核查；混合栏目用说明限定 |
| `access` | `free`、`registration`、`mixed`、`paid`、`unknown` | 免费、注册、公开与受限并存、付费、待核查 |
| `verificationStatus` | `verified`、`partial`、`unverified`、`unreachable` | 已核查、部分核查、未核查、暂不可达 |
| `entryType` | `栏目`、`机构首页` | 说明持续入口类型 |
| 资料 `kind` | `report`、`data-release`、`methodology`、`news` | 报告、数据发布、方法说明、新闻动态 |

`frequencyNote` 和 `accessNote` 不能省略。免费新闻稿不意味着完整数据库免费，产品宣称每小时更新也不证明维护者验证了动态刷新。各卡型、地区、币种、交付、合同期限或统计分母的差异写进 `caveats`。

## 6. 日期与核查状态

三种核心时间必须独立保存：

| 时间 | 字段 | 上述真实示例 |
|---|---|---|
| 数据所属期 | `Report.dataPeriod` | 2026 年第二季度，运营指标截至 6 月 30 日 |
| 发布日期 | `Report.publishedAt` | 2026-08-13 |
| 最近成功核查日期 | `Source/Report.verifiedAt` | 2026-10-04 |

`dataPeriod` 是描述口径的文本，可以包含单月和累计、期末时点及预测范围；它不是日期时间戳。只有报告年份或 PDF 路径，不能推出具体发布时间，技术报告年份也未必是数据统计期。未知时填写 `null`，页面将日期未知的报告放在已知发布日期之后。

此外，`Source.lastCheckAttemptAt` 记录最近一次尝试，即使访问失败也可更新；`maintainedAt` 记录目录编辑日期。这两个日期都不替代成功核查日期。日期采用亚洲/上海的日历日，不填写未来日期。

状态选择规则：

- `verified`：实际读取原栏目或对应原文，确认其身份与相关内容；填成功日期，并注明只验证公开部分还是完整文本。仅 HTTP 200 或标题可见不够。
- `partial`：仅搜索摘要、目录信息、试读或部分正文可核实。初次未成功读取原文时 `verifiedAt` 为 `null`，准确描述证据层级。
- `unverified`：尚未开展有效核查；`verifiedAt` 必须为 `null`。
- `unreachable`：本次工具无法读取目标入口。写明超时、HTTP 错误、空正文或登录阻挡等实际结果，不推断永久死链。

来源与报告分别评级。例如来源栏目能读，但方法公告只能检索到摘要，来源可以为 `verified`，方法报告应为 `partial`。如果曾成功核查、这次失败，可保留此前真实成功日期，并更新状态、尝试日期及说明；不能把本次失败日写成成功日，也不能无故抹去旧成功证据。

新增核查记录时，在 `docs/来源核查记录.md` 追加核查日期、原始 URL、状态与具体观察，并同步目录中的当前状态。该文档是审计记录，不是运行时第二份数据源。链接被反爬、登录或工具网络限制阻挡时，记录后继续维护其他来源；不要规避访问控制或购买订阅。

## 7. 验证、构建与同步

在项目根目录运行：

```powershell
pnpm validate
pnpm test
pnpm build
pnpm preview --host 127.0.0.1
```

`pnpm validate` 检查结构、枚举、ID 唯一性、分类与来源关联、日期和 HTTPS URL 格式；它不会访问远端网站，不能把“验证通过”写成“全部链接已核查”。`pnpm test` 验证筛选、去重、排序和日期规则；`pnpm build` 生成静态部署产物。记录自己实际执行的结果，不预先宣称通过。

然后通过终端提示的 HTTP 地址检查新增来源、详情、报告链接、组合筛选和未知日期表现。Homer 需要 HTTP 服务，不通过双击 `index.html` 验收。修改资料后刷新页面，确认能加载更新后的目录；部署文件以最终构建为准。

`dist/assets/catalog.json` 是构建时从 `public/assets/catalog.json` 复制的产物。正常维护只修改源文件再重新构建。若运维紧急改了部署包或 `dist`，必须把同一修改回写 `public/assets/catalog.json`，补做验证并重新生成构建，否则下一次构建会覆盖修改。不要将两个文件都当成独立维护入口。

首版没有网页编辑后台、账号权限、自动采集、自动核查或自动更新通知。打开导航不会为资料更新赋予新的成功核查日期；资料更新始终由维护者完成。

## 8. 东南亚专题

“东南亚专题”复用本目录。来源的 `tags` 包含 `东南亚专题` 时进入专题来源页；`regions` 只填写实际覆盖的国家，采用“新加坡、马来西亚、泰国、印尼、越南、菲律宾”标准名称。专题不新增研究分类，也不将全部亚太资料自动归入东南亚。

来源可增加 `trackingNote`（建议查看频率）、`subscriptionNote`（订阅或追踪方法）、`subscriptionUrl`（实际订阅页的 HTTPS 地址，无入口填 `null`）。`frequency` 和 `frequencyNote` 始终记录来源的真实发布节奏，不能把“建议每日查看”写成“每日固定发布”。订阅按钮仅打开原站，由读者自行提交信息。

专题文章必须独立填写 `regions`。动态筛选同时要求来源属于专题、文章有东南亚国家标签；不能把跨国运营商的全部新闻自动归入它覆盖的每个国家。历史无国家标签的资料仍在全站目录正常展示。`kind: news` 必须有非空的 `regions` 和 `stage`，例如“可研阶段”“投资计划”“草案报道”“入选开发”。报告可省略 `stage`，原有字段和结构版本 1 保持兼容。

原文已读到只表示核查了来源文本，不能将媒体报道等同于独立证实项目。对许可争议、监管草案和计划投资，在摘要、阶段及核查说明中限定事实层级。现场发电功率、IT 容量、规划容量、已签约容量与已投运容量不可相加或互换。报告介绍页与完整报告的阅读范围须分别说明；不知道具体发布日期时保留 `null`。
