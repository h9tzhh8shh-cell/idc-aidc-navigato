## 后续更新

1. 核查原始来源，修改 `public/assets/catalog.json`；字段规则见 [资料维护说明](资料维护说明.md)。
2. 运行 `pnpm validate`、`pnpm test`、`pnpm build`，检查本地页面。
3. 将修改提交到 GitHub 的 `main` 分支。Cloudflare 自动拉取、检查、构建并发布，无需再次手工上传静态文件。
4. 在 Cloudflare 项目 Deployments 页面确认新提交部署成功，再打开线上网址核对。

GitHub 网站编辑文件并提交到 `main` 也会触发发布。只修改本机文件、未提交到 GitHub，不会更新线上页面。网站资料没有定时抓取；自动部署只负责发布已经维护并提交的数据。需要更新资料时，可以在本对话提出更新范围。

## 文件范围与缓存

公开仓库排除 `node_modules`、`dist`、临时 `work` 及本站不使用的上游 `dummy-data/` 模拟接口目录。模拟数据中包含类似令牌、内网地址、邮箱的示例元数据；它们不属于本项目资料。原有本地副本仍保留。Homer 源组件、Apache-2.0 许可证和依赖版权说明已保留。

`public/_headers` 为首页、目录 JSON 和旧 Service Worker 设置 `Cache-Control: no-cache`。本站不注册离线 Service Worker，避免人工维护资料长期停留在旧缓存。

## 查看发布与回退

在 Cloudflare 控制台的 Workers & Pages 中打开 `idc-aidc-navigator`，查看 Deployments 和构建日志。构建失败时检查失败步骤，修复后重新提交；线上继续保留上次成功版本。若需要回退，选择一个已成功的生产部署执行回退，并同步修正 GitHub 源码，避免下一次提交重新发布错误内容。

本地 `origin` 指向项目仓库，`upstream` 保留 Homer 上游；本地 `main` 跟踪 `origin/main`。本次通过已授权的 GitHub 连接上传，未在本地配置个人访问令牌；本机直接 `git push` 仍需使用自己的 GitHub Git 登录。
